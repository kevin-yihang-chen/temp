## Current verified capabilities

The branch currently supports, on synthetic fixtures only:

1. selecting 3,500 ranker, 2,500 calibration, and 3,500 sealed formal source
   groups from a pinned DocVQA-train snapshot using the registered hash order;
2. rejecting prior-source, prior-RGB, and within-snapshot RGB collisions with
   deterministic reserve backfill;
3. reading only `docId` and image columns during allocation and verifying every
   row maps a `docId` to exactly one decoded-RGB digest;
4. independently rehashing every input and reproducing allocation and audit
   documents byte-for-byte;
5. freezing one alpha-1 hybrid factorized candidate, removing its development
   gate, and constructing an outcome-free source-balanced threshold sequence;
6. applying the registered 0.5% harm and 2% negative-call fixed-sequence tests
   on 2,500 source groups; and
7. retaining either a selected non-degenerate threshold or an answer-now
   failure without opening formal.

The 2,500-source calibration size is operationally meaningful: a small
400-source unit fixture cannot certify even an observed zero harm rate against
the 0.5% bound at per-risk cutoff 0.025, whereas the registered sample size can.
This observation does not change the preselected role size or statistical rule.

## Permitted execution order

Real execution starts only after the preregistered TextVQA one-shot branch
reaches its decision. The delay is for resource scheduling and cannot modify
the DocVQA protocol.

1. Freeze a clean implementation commit and run the entire test suite.
2. Acquire the pinned DocVQA-train Parquet shards without printing credentials.
3. Run identity allocation once against every frozen prior manifest, then run
   the independent recomputation audit.
4. Export only the ranker-training manifest; collect and audit its five-sibling
   rollouts and three label-free feature stages.
5. Fit exactly one registered candidate and freeze it while calibration and
   formal output directories are empty.
6. Export only the calibration manifest; collect and audit its rollouts and
   features; execute the fixed sequence exactly once.
7. On calibration failure, render the negative result and stop.
8. On calibration success, freeze the complete formal implementation and
   calibrated policy before materializing formal identities or targets.
9. Execute one formal chain and render the preregistered pass/fail decision.

Every submitted compute job must retain state-change email notification. An
interrupted job may resume only an identical checkpoint under the same hashes.
No GitHub publication is part of this execution procedure.
